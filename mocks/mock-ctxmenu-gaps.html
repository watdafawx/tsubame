Six states the approved context menu mock does not draw. Same tokens, same menu primitives, same editor rows as mock-ctxmenu.html (state 6b is the baseline). Each state is a proposal: nothing is built until it is approved. Page-only parameters for screenshots: ?only=<id>&theme=light&dens=26&sc=125&ul=0. Review notes (grey labels, captions) are not part of the app.

1Row “…” menu, in Settings and in the menu itself

One fixed list of rows for every kind of item, so the muscle memory is the same everywhere. Rows that do not apply to that kind of item are disabled, not removed (Pin and groups are for Windows’ and apps’ items; Move up / down are for Tsubame’s own rows). Delete exists only on custom and imported entries.

2Refresh from last menu

The button keeps the place the approved mock gave it: second toolbar row, between Import and Reset. Five states of that row.

3Pin control in the Settings rows

A pin cell between “Comes from” and the … button. Pinned rows sit first in their group, with the grip locked.

4Naming a user group inside the real menu

Today a user group is a block between separators with no header. Two variants, same menu.

5Nilesoft import: choose what to import

Opens after the file dialog (or “Review and import…” on the detected-file note) and before anything is written.

6Kind switch: Several items and Drive

File / Folder / Empty area / Several items / Drive. Each kind has its own list and its own learned items.
